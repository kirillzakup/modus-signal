# ИИ-агент собственника

Агент каждый день разбирает работу с обращениями и отвечает на вопросы собственника:
что висит, кто активен, кто требует внимания, кого поощрить, где риски и что поменять в процессе.

## Как это работает

```
данные системы ──► core.ownerDigest() ──► core.agentPrompt() ──► LLM ──► отчёт / ответ
(обращения, SLA,     (агрегированный        (роль агента +          (Claude или     (сохраняется,
 баллы, чат)          разбор в JSON)         данные + формат)        OpenAI-совм.)    уходит в Telegram)
```

1. **Данные.** Сервер берёт текущее состояние: обращения и их статусы, сроки SLA, просрочки, эскалации,
   начисления баллов, заявки на награды, активность в общем чате.
2. **Дайджест.** `core.ownerDigest` сводит это в компактный JSON: пульс процесса (0–100), KPI, висящие обращения,
   активные сотрудники, «требуют внимания», «к поощрению», «зона риска», корректировки, следующие шаги.
   Тот же дайджест без ИИ превращается в текст по правилам (`core.digestText`) — это запасной вариант.
3. **Промпт.** `core.agentPrompt(digest, question?)` задаёт роль («ИИ-агент собственника ГК «Модус Трейд»»),
   требования (только факты из данных, ссылки на A-xxx, кадровое решение — за собственником) и формат ответа.
4. **LLM.** Сервер отправляет промпт выбранной модели и сохраняет ответ как отчёт (`source: "ai"`).
   Если модель не подключена или недоступна — сохраняется отчёт по правилам (`source: "rules"`), работа не прерывается.

Где это используется:
- `POST /api/owner/report` — отчёт сейчас; `GET /api/owner/reports` — история;
- `POST /api/agent/ask` — вопрос агенту (с историей диалога до 6 реплик);
- ежедневный отчёт в `REPORT_HOUR` + Telegram-команды `/report` и `/ask`.

## Какие данные уходят в LLM

- Только **агрегированные рабочие данные из системы**: номера и заголовки обращений, статусы, сроки, имена/роли
  сотрудников в системе, счётчики активности и баллов, заявки на награды.
- **Не отправляются:** файлы и вложения, полные тексты переписки в чате, Telegram ID, ключи и настройки.
- **Анонимные обращения** остаются анонимными: в дайджест не попадает их автор.
- Ключ API хранится только в переменных окружения сервера и никогда не пишется в логи и не отдаётся в браузер.

Если данные не должны покидать контур компании — подключите локальную модель (см. ниже).

## Подключение

### Claude (Anthropic) — по умолчанию
```bash
LLM_API_KEY=sk-ant-...          # или ANTHROPIC_API_KEY
# LLM_MODEL=claude-sonnet-5-5   # по умолчанию
```
Запрос: `POST https://api.anthropic.com/v1/messages`, заголовки `x-api-key`, `anthropic-version: 2023-06-01`.

### OpenAI и совместимые (OpenRouter, шлюзы к YandexGPT / GigaChat и т. п.)
```bash
LLM_PROVIDER=openai
LLM_API_KEY=sk-...              # или OPENAI_API_KEY
LLM_MODEL=gpt-4o-mini           # по умолчанию
# LLM_BASE_URL=https://openrouter.ai/api/v1
```
Запрос: `POST {LLM_BASE_URL}/chat/completions`, заголовок `Authorization: Bearer …`.

### Локальная модель (Ollama, vLLM, LM Studio) — данные не покидают сервер
```bash
LLM_PROVIDER=openai
LLM_BASE_URL=http://127.0.0.1:11434/v1   # Ollama
LLM_MODEL=qwen2.5:14b
# ключ не нужен
```

Общие параметры: `LLM_MAX_TOKENS` (по умолчанию 1500), тайм-аут ответа — 90 секунд.
Проверка: `GET /api/health` → `"llm": { "configured": true, "provider": "…", "model": "…" }`.

## Ежедневный отчёт

- `REPORT_HOUR` — час (0–23, по умолчанию 9) по часовому поясу сервера (`TZ`, например `Asia/Almaty`).
- Сервер проверяет расписание раз в минуту; за сутки создаётся **один** отчёт (созданный вручную тоже считается).
- Собственники получают уведомление в колокольчике, а с привязанным Telegram — полный текст отчёта
  и кнопку «Открыть панель собственника».

## Важно про выводы о людях

Агент видит только то, что отражено в системе, а не всю работу человека. Поэтому разделы «Требуют внимания»
и «Зона риска» — это **рекомендации** на основе фактов (просрочки, ответ в срок, эскалации), а не решения.
Агент предлагает разговор 1:1 и план исправления; **окончательное кадровое решение всегда принимает собственник**.
