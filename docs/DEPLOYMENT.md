# Запуск и развёртывание

## GitHub Pages: публичная демонстрация

1. Разместите проект в `kirillzakup/modus-signal`, основная ветка — `main`.
2. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Во вкладке **Actions** запустите **Tests and GitHub Pages** или отправьте изменения в `main`.
4. Workflow выполнит `npm ci`, `npm test`, `npm run build`, затем опубликует `dist/pages/`.
5. После успешного deploy откройте `https://kirillzakup.github.io/modus-signal/`.

Если скопировали проект в другой репозиторий, замените ссылки в README на его адрес. Путь к приложению должен включать имя репозитория. Маршруты интерфейса используют `#`, поэтому переход по карточке не требует серверной переадресации.

Pages публикует только статическое демо. Серверная SQLite-база, ключи и конфигурация рабочей компании не входят в артефакт. Не добавляйте ключ DeepSeek в GitHub Pages: там нет серверной среды для его безопасного использования.

Параметры workflow основаны на [официальной инструкции GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Codespaces: сервер из репозитория

Нажмите кнопку Codespaces в README. Конфигурация `.devcontainer/devcontainer.json` устанавливает Node.js 24, выполняет `npm ci` и запускает сервер. Порт `8080` появится в панели **Ports**; лог — `/tmp/modus-signal.log`.

Оставляйте порт приватным: демонстрационный режим позволяет выбирать учебного пользователя. Локальная база находится в `data/`. При удалении codespace его файлы могут быть удалены, поэтому нужные данные сохраните заранее. После работы остановите среду, чтобы не расходовать её квоту.

Для собственного ключа используйте секреты Codespaces или локальный `.env`, который не попадает в Git. После изменения окружения перезапустите процесс сервера. Инструкция по устройству окружения — в [документации dev containers](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/introduction-to-dev-containers).

## Node.js и Docker

Для запуска на компьютере:

```bash
npm ci
npm start
```

По умолчанию сервер слушает `8080`, база хранится в `data/`. Переменные `HOST`, `PORT` и `DATA_DIR` позволяют изменить параметры. Для локального файла окружения используйте:

```bash
node --env-file=.env --disable-warning=ExperimentalWarning server/index.js
```

Запуск Docker с отдельным томом:

```bash
docker build -t modus-signal .
docker run --rm -p 127.0.0.1:8080:8080 -v modus-data:/data modus-signal
```

Добавить свои настройки можно параметром `--env-file .env`. Сам файл не включайте в образ. База должна находиться в постоянном томе, а не только в изменяемом слое контейнера. Перед резервным копированием файлов SQLite остановите приложение или используйте корректный механизм резервного копирования SQLite.

Node.js-режим предназначен прежде всего для демонстрации и разработки. Он не воспроизводит автоматически cookie-сессии и Telegram-регистрацию Cloudflare-версии. Не публикуйте `DEMO=1` как защищённый рабочий кабинет.

## Cloudflare: общая рабочая версия

Перед публикацией настройте **свой** проект в `wrangler.jsonc`: имя Worker, аккаунт, Durable Object binding и правила миграции. Конфигурация другого аккаунта не должна использоваться по умолчанию. Скрипт `scripts/cloudflare.cjs` проверяет соответствие выбранному аккаунту перед публикацией.

```bash
npm ci
npm run cloudflare:login
npm run build:cloudflare
npm run deploy:cloudflare
```

`build:cloudflare` выполняет только проверку сборки. `deploy:cloudflare` изменяет облачный Worker. До его запуска проверьте активный аккаунт и целевой проект. GitHub Pages workflow сам не разворачивает Cloudflare.

| Настройка | Для чего |
| --- | --- |
| `BOT_TOKEN` | Серверная проверка Telegram и работа бота |
| `DEEPSEEK_API_KEY` | Запросы личного помощника |
| `DEEPSEEK_MODEL` | Модель DeepSeek; по умолчанию `deepseek-flash` |
| `TELEGRAM_GROUP_ID` | Проверка членства в выбранной группе |
| `BOT_USERNAME` | Имя собственного бота для входа |
| `PUBLIC_URL` | HTTPS-адрес вашей опубликованной версии, где он требуется интеграцией |

Секреты передавайте интерактивно в Cloudflare:

```bash
node scripts/cloudflare.cjs secret put BOT_TOKEN
node scripts/cloudflare.cjs secret put DEEPSEEK_API_KEY
```

Команды запросов секретов не требуют вставлять значение в исходники или историю команд. Для настоящих ответов DeepSeek нужен пополненный баланс API. Ошибка оплаты означает необходимость проверить кабинет поставщика, а не проблему регистрации сотрудника.

Настройте своего бота через BotFather: адрес Mini App должен указывать на вашу HTTPS-версию. Добавьте бота в нужную группу и выдайте права только для используемых функций. Настройка webhook, расписания отчётов и секретов относится к вашей серверной установке; публичная демонстрация её не выполняет.

Первичную настройку и отдельные учётные записи собственника и администратора создайте в серверной версии. После этого проверьте регистрацию через Telegram, имя и должность сотрудника, доступ к карточке и недоступность управленческих функций обычному сотруднику.

## Проверка после запуска

1. Откройте `/api/health`: сервер должен отвечать JSON без секретов.
2. Создайте учебную проблему и задайте сроки предложений, голосования и решения.
3. Пройдите сценарий несколькими сотрудниками: варианты → голосование → план → результат.
4. Проверьте историю монет и заявку на награду.
5. Задайте личному помощнику вопрос. При неподключённом API ожидается понятная ошибка, а не имитация успешного ответа.
6. Проверьте кабинет собственника и скачивание PDF в серверной конфигурации.
7. Перезапустите сервер и убедитесь, что общие данные сохранились.

## Если не работает

| Симптом | Проверка |
| --- | --- |
| Pages показывает 404 | Успешен ли deploy, выбран ли GitHub Actions в Settings → Pages, верно ли имя репозитория в URL |
| Workflow не находит `dist/pages/index.html` | Запустите `npm run build` локально и проверьте сборщик; не загружайте вместо артефакта весь репозиторий |
| `node:sqlite` не найден | Используйте Node.js 24 |
| Codespaces: порт не открыт | Посмотрите `/tmp/modus-signal.log` и панель Ports; после ручной остановки запустите `npm start` |
| ИИ сообщает о настройке или оплате | Проверьте серверный ключ, модель и баланс DeepSeek |
| Telegram не пускает сотрудника | Проверьте настройки своего бота, группы, подпись входа и активность сотрудника |
| После Docker-перезапуска пропали данные | Убедитесь, что `/data` подключён к тому же именованному тому |

Не прикладывайте секреты, приватные отчёты или рабочую базу к публичному issue. Для воспроизведения используйте учебные данные.
