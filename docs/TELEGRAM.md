# МОДУС · СИГНАЛ в Telegram: бот и Mini App

Пошаговая настройка: от создания бота до привязки сотрудников.

## 1. Создайте бота в @BotFather

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Имя: `МОДУС · СИГНАЛ`, username, например: `modus_signal_bot`.
3. Сохраните токен вида `1234567890:AA…` — это `BOT_TOKEN`. Никому его не передавайте.
4. (Рекомендуется) `/setdescription` и `/setabouttext`: «Ваш голос в улучшениях компании».
5. (Рекомендуется) `/setuserpic` — логотип.

Команды (`/start`, `/new`, `/my`, `/inbox`, `/report`, `/ask`, `/help`) и кнопку меню **«Сигнал»** сервер
устанавливает сам при запуске (`setMyCommands`, `setChatMenuButton`) — вручную их задавать не нужно.

### Mini App по прямой ссылке (необязательно)

Если нужна ссылка вида `https://t.me/modus_signal_bot/signal`:
`/newapp` → выберите бота → название, описание, картинка 640×360 → URL = ваш `PUBLIC_URL` → короткое имя `signal`.

## 2. Опубликуйте приложение по HTTPS

Telegram открывает Mini App только по **https**. Сервер слушает HTTP на `PORT` (8080) — поставьте перед ним обратный прокси.

### Вариант A: Caddy (сертификат выпускается автоматически)

`/etc/caddy/Caddyfile`:
```
signal.example.ru {
    encode gzip
    reverse_proxy 127.0.0.1:8080
}
```
```bash
sudo systemctl reload caddy
```

### Вариант B: nginx + certbot

```nginx
server {
    listen 443 ssl http2;
    server_name signal.example.ru;
    ssl_certificate     /etc/letsencrypt/live/signal.example.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/signal.example.ru/privkey.pem;
    client_max_body_size 1m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```
Не добавляйте `X-Frame-Options: DENY` — веб-версия Telegram открывает Mini App во фрейме.

Для локальной отладки подойдёт туннель (`cloudflared tunnel --url http://localhost:8080` или аналог) — его https-адрес и будет `PUBLIC_URL`.

## 3. Запустите сервер с переменными окружения

```bash
export BOT_TOKEN=1234567890:AA...
export PUBLIC_URL=https://signal.example.ru
export DEMO=0                  # боевой режим: вход только через Telegram
export DATA_DIR=/var/lib/modus-signal
export TZ=Asia/Almaty          # часовой пояс для сроков в уведомлениях
npm start
```

Docker:
```bash
docker build -t modus-signal .
docker run -d --name modus-signal -p 127.0.0.1:8080:8080 \
  -v modus-data:/data \
  -e BOT_TOKEN=... -e PUBLIC_URL=https://signal.example.ru -e DEMO=0 -e TZ=Asia/Almaty \
  --env-file ./link-codes.env \
  modus-signal
```

Проверка: `curl https://signal.example.ru/api/health` → `"bot": true`. В логах: `[bot] Telegram-бот запущен`.

Бот работает через long polling (`getUpdates`), входящие порты и вебхук не нужны.
Запускайте **один** экземпляр сервера на токен — иначе Telegram вернёт ошибку 409 Conflict.

## 4. Привязка сотрудников

Каждый сотрудник в системе имеет идентификатор (`u1`, `m1`, `a1` …). Telegram-аккаунт связывается с ним через поле `tgId`.

### Демо-режим (`DEMO=1`)

- В боте: `/start` → кнопки с ролями → нажать нужную. Повторный `/start` позволяет сменить роль.
- В Mini App: при ответе `401 {code:"link_required"}` интерфейс показывает выбор роли и вызывает
  `POST /api/tg/link {"userId":"u4"}` с заголовком `Authorization: tma <initData>`.

### Боевой режим (`DEMO=0`)

1. Администратор задаёт одноразовые коды в окружении сервера — по переменной на сотрудника:
   ```
   LINK_CODE_u1=7F3K-91QA
   LINK_CODE_m1=Q2W8-ZX11
   ```
   (удобно хранить в отдельном файле `link-codes.env`, подключаемом через `--env-file`; после изменения — перезапуск).
2. Передаёт сотруднику его идентификатор и код лично.
3. Сотрудник открывает бота и отправляет `/link u1 7F3K-91QA` — или вводит код в экране привязки Mini App
   (`POST /api/tg/link {"userId":"u1","code":"7F3K-91QA"}`).
4. После привязки код можно удалить из окружения — повторная привязка потребует нового кода.

Администратор также может привязать вручную: `PUT /api/admin/users/u1 {"tgId":"123456789"}`
(Telegram ID пользователь узнаёт, например, у @userinfobot).

Один Telegram-аккаунт = один сотрудник: новая привязка снимает старую.

## 5. Что умеет бот

| Команда | Действие |
|---|---|
| `/start` | Приветствие «Ваш голос в улучшениях компании», кнопка «Открыть МОДУС · СИГНАЛ»; в демо — выбор роли |
| `/new` | Быстрое обращение в чате: тип → категория → описание → решение (для проблемы можно «Пропустить», для предложения обязательно) → номер, ответственный и срок первого ответа |
| `/my` | Последние 10 своих обращений со статусами и отметкой ⏰ о просрочке |
| `/inbox` | Для ответственных и собственника: открытые обращения в зоне ответственности, просроченные — первыми |
| `/report` | Собственник/администратор: отчёт ИИ-агента за сегодня (если его нет — формируется сразу) + заявки на награды, ждущие подтверждения |
| `/ask вопрос` | Собственник/администратор: вопрос ИИ-агенту, например `/ask Кто тормозит обращения?` |
| `/help` | Справка |

**Уведомления.** Каждые 15 секунд сервер отправляет новые уведомления (назначение, смена статуса, ответ,
эскалация) сотрудникам с привязанным Telegram — с кнопкой, открывающей карточку обращения в Mini App
(`PUBLIC_URL#/t/A-021`). Сотрудники без Telegram видят уведомления в колокольчике веб-приложения.

**Ежедневный отчёт.** В `REPORT_HOUR` (по умолчанию 9:00 по `TZ` сервера) агент формирует отчёт;
собственники с привязанным Telegram получают его полный текст (длинный отчёт приходит несколькими сообщениями)
с кнопкой «Открыть панель собственника» (`PUBLIC_URL#/owner`). Подробнее — [AI_AGENT.md](AI_AGENT.md).

Обычные сообщения боту вне сценария `/new` не публикуются в общий чат — общий чат доступен в Mini App.

## 6. Безопасность

- Подпись `initData` проверяется на сервере (HMAC-SHA256, ключ `WebAppData` + `BOT_TOKEN`), срок — не старше 24 часов.
- В боевом режиме обязательно `DEMO=0`: иначе любой может войти под любым пользователем через `X-Demo-User`.
- Ограничьте `CORS_ORIGIN` вашим доменом, если API и интерфейс на одном адресе.
- Регулярно копируйте `DATA_DIR/modus.db*` (SQLite в режиме WAL: копируйте все три файла или используйте `sqlite3 modus.db ".backup backup.db"`).


## Версия 5: фильтр собственника в боте

- Каждое новое обращение бот присылает собственнику и заместителю с текстом, контактом автора и двумя кнопками: «В работу» и «В корзину».
- «В работу» в один тап назначает ответственного по категории и стандартный срок; изменить их можно в карточке.
- «В корзину» отправляет обращение в корзину с причиной «Не по теме»; вернуть его можно в разделе «Входящие» → «Корзина».
- Если обращение ждёт решения дольше 24 часов, бот напоминает раз в сутки.
- Команда `/new` при включённом фильтре спрашивает только текст: категорию и приоритет ставит собственник.
